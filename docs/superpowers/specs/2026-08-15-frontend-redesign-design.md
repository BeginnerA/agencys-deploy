# 前端重设计规格：深蓝科技风运维平台

> 日期：2026-08-15
> 状态：已由用户确认（视觉伴侣 approve）
> 范围：webapp 前端纯 UI 重构 + 告警中心聚合页 + 参考图仪表盘复刻，后端零改动

## 1. 背景与目标

现有前端为 Flask + 原生 HTML/CSS/JS + ECharts 的单页大屏（`screen.html` + 抽屉弹窗），UI 与交互均不理想。本次参考「Perfview IT 大数据运维管理平台」深蓝科技风 UI，对前端进行整体重设计：

- 深蓝暗黑科技风，左侧垂直导航 + 顶部栏 + 面包屑的多页面结构
- 完整复刻参考图的监控大屏（雷达健康指数、机房环境检测、趋势图等）
- 新增「告警中心」聚合页（从任务失败/服务异常数据聚合，无新后端数据源）
- 保留现有全部功能：登录、发布/回滚、任务日志、服务器状态、配置管理（项目/服务/环境/流水线/服务器/用户/YAML 导入导出）

**硬约束：后端 API 零改动**。所有新 UI 仅消费现有接口。

## 2. 技术方案

| 项 | 决策 |
|---|---|
| 技术栈 | 原生 HTML/CSS/JS + ECharts（沿用），**零构建链、零 npm 依赖** |
| 路由 | SPA hash 路由（`#/dashboard`、`#/deploy`、`#/alerts`、`#/logs`、`#/config/...`），单模板 + JS 渲染 |
| 设计系统 | CSS 变量（`:root` 中定义语义 token），组件样式通过 token 组合 |
| 品牌名 | `window.PLATFORM_NAME` 全局变量，默认"智能运维平台"，一处修改全局生效 |
| 认证 | 沿用 JWT（`localStorage` + `Authorization: Bearer`），401 自动跳登录 |
| 图表 | 延续 ECharts（`static/vendor/echarts.min.js`），新页面按需初始化 |
| 响应式 | 1920 主设计基准，1280 断点降级（导航折叠、卡片网格收缩），内容区横向滚动兜底 |

## 3. 设计系统（Design Tokens）

### 3.1 色板（深蓝科技风）

| Token | 值 | 用途 |
|---|---|---|
| `--bg-base` | `#0A142F` | 页面主背景 |
| `--bg-panel` | `#0D1B33` | 卡片/面板背景 |
| `--bg-panel-2` | `#112241` | 悬浮/次级面板 |
| `--border` | `rgba(0,212,255,.15)` | 边框/分隔线 |
| `--primary` | `#00D4FF` | 主色青：强调、选中、链接 |
| `--success` | `#00E396` | 正常/成功（绿） |
| `--warning` | `#FEB019` | 警告（黄） |
| `--danger` | `#FF4560` | 异常/失败（红） |
| `--accent` | `#FF7A45` | 强调橙（运行中/注意） |
| `--text-1` | `#E6F1FF` | 主文字 |
| `--text-2` | `#8FA8C8` | 次级文字 |
| `--text-3` | `#5A7296` | 弱化文字/占位 |

### 3.2 字体与排版

- 字体栈：`"Microsoft YaHei", "PingFang SC", system-ui, sans-serif`；数字/指标用 `"DIN Alternate", "Roboto Mono", monospace` 增强科技感
- 字号阶梯：11 / 12 / 13 / 14 / 16 / 20 / 24 / 32px（标题、指标数字、正文、辅助文字分级）

### 3.3 间距 / 圆角 / 阴影

- 间距阶梯：4 / 8 / 12 / 16 / 24 / 32 / 48px
- 圆角：面板 10px，卡片 8px，按钮/输入 6px
- 阴影：`0 4px 16px rgba(0,0,0,.35)` 面板投影 + 主色辉光 `0 0 12px rgba(0,212,255,.25)` 仅用于重点元素

### 3.4 动效

- 过渡：`all .25s cubic-bezier(.4,0,.2,1)`
- 悬停：面板轻微上浮 `translateY(-2px)` + 边框主色
- 导航激活：左侧 3px 主色指示条 + 背景渐变
- 数值变化：大屏指标数字轻微闪烁高亮（CSS animation，1.2s）

- **左侧导航**：可折叠（窄 64px 图标模式 / 宽 220px 图文模式）；分组：运维监控（监控中心、项目总览）、运维操作（发布中心、告警中心、日志中心）、系统管理（配置管理，admin 可见）；告警中心带 `99+` 红色角标（实时轮询告警数）

- **底部**：保留跑马灯（最近发布事件滚动条），可关闭

## 6. 监控中心大屏（参考图复刻重点）

参考图核心视觉元素逐项映射：

### 6.1 顶部 KPI 指标条
一行 4~6 个指标卡：项目数、服务数、环境数、服务器数、任务总数、发布成功率。每个指标卡：图标 + 数值（大号 DIN 字体）+ 标签 + 底部微光条。

### 6.2 雷达健康指数（示例数据）
- ECharts radar：维度 = 稳定性/性能/资源/安全/可用性/响应
- 数据来源：**示例数据 + 真实数据加权**——可用性取真实成功率，其余维度由服务在线率/失败任务数归一化生成（前端计算，后端零改动）；无真实数据时显示示例值并标注"演示数据"
- 视觉：半透明填充 + 主色描边 + 辉光

### 6.3 机房环境检测（示例数据）
- 温度/湿度/功耗/风扇 4 项仪表盘（ECharts gauge），示例数据 + 轻微随机扰动（每 5s 刷新模拟）
- 标注"演示数据"徽标，与真实监控区分

### 6.4 发布趋势
- 近 7 日 / 30 日切换：柱状（成功绿/失败红叠加）+ 折线（成功率）双轴
- 数据：`overview.trend7 / trend30`

### 6.5 服务器状态
- 表格：主机、环境、SSH 连通状态（绿/红点）、容器数、最后探测时间
- 数据：`monitor/overview.servers`

### 6.6 最近发布 / 运行中任务
- 右侧列表：任务名、环境、版本、状态徽标、时间；运行中任务自动轮询刷新（3s），失败可点开日志

## 7. 告警中心聚合逻辑（前端，无新后端）

- **数据源**：`GET /api/tasks?limit=500` + `GET /api/dashboard/overview`，前端每 15s 轮询
- **告警生成规则**：
  1. 状态 `failed` 的任务 → 级别按类型：回滚失败=严重、发布失败=警告
  2. 状态 `running` 超过 30 分钟 → 超时告警（警告）
  3. `monitor/overview` 中 `status = probe_failed` 或 `not_deployed` 且该服务 `enabled` → 服务异常（警告）
- **状态流转**：默认未处理；用户可单条标记"已处理"（localStorage 持久化，key `alert_acked_<taskId>`）；重新出现的新告警自动恢复未处理
- **展示**：告警列表（级别徽标、来源类型、内容、时间、状态、操作）+ 顶部统计（未处理/已处理）+ 级别筛选 tab + 左侧导航角标 = 未处理数（>99 显示 99+）

## 9. 关键交互约定

- **发布流程**（沿用现有语义）：项目总览卡片 → 点击"发布"→ 抽屉表单（版本/环境/回滚/自动版本/跳过构建）→ 提交后跳发布中心看进度
- **任务日志**：右侧滑出抽屉，offset 轮询增量加载，运行中自动追尾，`running→success/failed` 停止
- **运行中任务终止**：任务详情内"终止"按钮 → 二次确认弹窗 → `POST /tasks/<id>/kill`
- **配置 CRUD**：列表 → 抽屉表单编辑；删除一律二次确认；服务被流水线引用时展示后端错误提示
- **全局错误处理**：`api()` 抛错 → toast 顶部红色提示；401 → 清 token 跳登录
- **加载态**：页面骨架屏（面板级 shimmer），避免白屏

## 10. 响应式与降级

- 1920+：完整布局，大屏内容区最大 1680px 居中
- 1280~1919：左侧导航折叠为 64px 图标模式；卡片网格 4 列→2 列；KPI 条换行
- <1280：内容区允许横向滚动（运维工具以桌面为主，不做移动端适配）
- 大屏图表面板统一 `min-width` 保护，防止 ECharts 塌陷

## 11. 登录页重设计

- 深蓝渐变背景 + 网格光效 + 居中玻璃拟态登录卡片
- 品牌 Logo + 平台名 + 用户名/密码 + 登录按钮（加载态）
- 错误提示 toast；首次登录强制改密弹窗沿用
- 登录成功 → `location.href = '/screen#/dashboard'`

## 12. 错误处理与空态

- 接口失败：面板内局部错误态（图标 + 重试按钮），不整页崩溃
- 空数据：统一空态组件（图标 + 文案 + 引导按钮），如"暂无告警""暂无任务"
- 监控未启动（`monitor/overview` 空）：显示"实时探测未启用"提示条，并给出启动参数说明

## 13. 测试计划

1. **手工冒烟**（每页）：登录 → 六页面导航切换 → 面包屑正确 → 无 console 报错
2. **发布闭环**：服务卡片发布 → 任务出现 → 日志追尾 → 状态流转 → 终止/失败场景
3. **告警闭环**：制造失败任务 → 告警中心出现未处理告警 → 标记已处理 → 角标数更新
4. **配置 CRUD**：六类各建/改/删一次，YAML 导入导出按钮可用
5. **权限**：viewer 不见"配置管理"；operator 可发布不可配置
6. **响应式**：1280 窗口检查导航折叠与网格降级
7. **回归**：现有 API 全部可被新前端调用（无 404/500）

## 14. 假设与边界

- 后端接口、DB 结构、认证机制一律不改
- 雷达健康指数、机房环境检测为展示性数据（标注"演示数据"），不影响真实运维判断
- 告警"已处理"状态存 localStorage（单浏览器生效），不做多用户共享
- 品牌名默认沿用"智能运维平台"，经 `window.PLATFORM_NAME` 可配置
- 浏览器目标：Chrome/Edge 最新两个大版本
