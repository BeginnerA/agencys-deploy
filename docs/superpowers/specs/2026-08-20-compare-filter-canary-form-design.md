# 发布对比环境筛选 & 灰度策略表单化配置 — 设计规格

## 概述

对发布增强模块进行两项体验优化：1）发布对比页增加环境筛选 + 快照任意选择能力，修复当前前后端断裂的对比功能；2）灰度策略配置从 JSON textarea 改为模板驱动的表单化编辑器，降低配置门槛。

---

## 1. 需求决策汇总

| 功能 | 决策 |
|------|------|
| 发布对比 - 环境筛选 | 工具栏环境下拉，切换后自动刷新对比 |
| 发布对比 - 快照选择 | 默认对比最近两次；可展开面板任意选两条 |
| 发布对比 - 跨环境 | 支持左右两列分别选不同环境的快照 |
| 灰度策略 - 配置方式 | 预设模板 + 表单微调，替代 JSON textarea |
| 灰度策略 - 模板数量 | 4 个内置模板 + 自定义空白 |
| 灰度策略 - 预览 | 实时条形图预览发布节奏 |

---

## 2. 功能一：发布对比增强

### 2.1 现状问题

- 后端 `GET /api/deploy/compare` 要求 `project_id` 和 `env` 参数必填
- 前端 `deploy_compare.js` 调用时未传 `env`，导致 API 返回 400
- 工具栏只有项目选择器，无环境筛选

### 2.2 前端交互设计

**工具栏**：
- 项目选择器（已有）+ 环境下拉（新增）+ 「选择快照对比」按钮（新增）
- 切换项目时重建环境选项（与 deploy.js 的 loadFilters 模式一致）
- 切换环境后自动对比该环境最近两次快照

**快照选择面板**（点击「选择快照对比」展开/折叠）：
- 左右两列，分别选择「旧版本」和「新版本」
- 每列列出当前项目**所有环境**的快照（带环境标签区分），radio 单选
- 左右可选不同环境的快照（跨环境对比）
- 「开始对比」按钮触发对比

**对比结果区**：
- 保持现有表格样式（服务名、旧版本、新版本、变化标记）
- 底部显示 Nacos 配置 / 环境变量变更状态

### 2.3 后端 API 变更

现有 `GET /api/deploy/compare` 需扩展参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| project_id | int | 是 | 项目 ID |
| env | string | 否* | 环境名（默认模式时必填） |
| old_id | int | 否 | 旧快照 ID（手动选择模式） |
| new_id | int | 否 | 新快照 ID（手动选择模式） |

**两种模式**（互斥，前端只发一种）：
1. **默认模式**：传 `project_id` + `env`（不传 old_id/new_id），取该环境最近两条快照对比
2. **手动模式**：传 `old_id` + `new_id`（两个都必须传），按 ID 取两条快照对比，忽略 project_id/env

后端判定逻辑：若 `old_id` 和 `new_id` 都存在则走手动模式，否则走默认模式（要求 project_id + env）。

### 2.4 前端文件变更

| 文件 | 变更 |
|------|------|
| `webapp/static/js/pages/deploy_compare.js` | 重写：增加环境下拉、快照选择面板、两种对比模式 |

## 3. 功能二：灰度策略表单化配置

### 3.1 现状问题

- 新建策略时批次配置使用 JSON textarea，用户需手写 JSON 数组
- 格式要求严格（引号、逗号、括号），非技术用户难以使用
- 无校验反馈，JSON 解析失败仅提示"格式错误"

### 3.2 前端交互设计

**新建/编辑表单**（在 drawer 中）：

1. **基础信息区**：策略名称（input）+ 所属项目（select）
2. **模板选择区**：胶囊按钮组，点击填充批次配置
   - 标准三批：1台(5min,自动) → 2台(10min,自动) → 全量(0min,人工)
   - 快速两批：1台(3min,自动) → 全量(0min,人工)
   - 保守五批：1台(5min,人工) → 2台(10min,自动) → 3台(15min,自动) → 5台(10min,自动) → 全量(0min,人工)
   - 全量一次：全量(0min,人工)
   - + 自定义：清空批次，添加一个空白行
3. **批次编辑器**：表格化行编辑器
   - 每行字段：序号 | 服务器数量（input/下拉选"全部"）| 观察时间分钟（input）| 推进方式（select：自动推进/人工确认）| 删除按钮
   - 底部「+ 添加批次」按钮
4. **实时预览**：横向条形图，高度映射服务器数量，标注台数和观察时间
5. **底部**：设为默认复选框 + 保存按钮

**编辑已有策略**：
- 打开 drawer 时回填现有数据
- 不自动匹配模板（模板仅用于新建时快速填充）

### 3.3 模板数据结构

模板定义为前端常量，不存数据库：

```javascript
const CANARY_TEMPLATES = {
  standard: {
    name: '标准三批',
    steps: [
      { servers: 1, observe_minutes: 5, auto_advance: true },
      { servers: 2, observe_minutes: 10, auto_advance: true },
      { servers: 'all', observe_minutes: 0, auto_advance: false }
    ]
  },
  quick: {
    name: '快速两批',
    steps: [
      { servers: 1, observe_minutes: 3, auto_advance: true },
      { servers: 'all', observe_minutes: 0, auto_advance: false }
    ]
  },
  conservative: {
    name: '保守五批',
    steps: [
      { servers: 1, observe_minutes: 5, auto_advance: false },
      { servers: 2, observe_minutes: 10, auto_advance: true },
      { servers: 3, observe_minutes: 15, auto_advance: true },
      { servers: 5, observe_minutes: 10, auto_advance: true },
      { servers: 'all', observe_minutes: 0, auto_advance: false }
    ]
  },
  full: {
    name: '全量一次',
    steps: [
      { servers: 'all', observe_minutes: 0, auto_advance: false }
    ]
  }
};
```

### 3.4 后端变更

**无需修改**。现有 API 已接受 `steps` 数组，前端表单最终序列化为相同的 JSON 格式提交。

### 3.5 前端文件变更

| 文件 | 变更 |
|------|------|
| `webapp/static/js/pages/deploy_canary.js` | 重写：模板选择 + 表单编辑器 + 预览替代 JSON textarea |

## 4. 错误处理

| 场景 | 处理方式 |
|------|---------|
| 发布对比 - 环境无快照 | 显示空状态提示"该环境暂无发布记录" |
| 发布对比 - 手动选择同一快照 | 禁用「开始对比」按钮，提示"请选择两条不同的快照" |
| 发布对比 - API 返回不足 2 条 | 显示"至少需要 2 条发布记录才能对比" |
| 灰度策略 - 批次为空 | 保存时校验，提示"至少需要一个批次" |
| 灰度策略 - 观察时间为负数 | input 限制 min=0 |
| 灰度策略 - 服务器数量非法 | input 限制 min=1 或选"全部" |

## 6. 约束与假设

- 后端 `deployment_snapshots` 表已有 `env` 字段，快照列表 API 已支持 env 筛选
- 灰度策略的数据模型（`canary_configs` 表 + `steps` JSON 字段）不变
- 模板定义硬编码在前端 JS 中，不做后端模板管理
- 发布对比的跨环境对比需要后端小改（支持 old_id/new_id 参数）
