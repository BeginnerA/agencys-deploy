01 / PIPELINE

一条发布链，
六个检查点。

服务或整条流水线排进队列后，平台按顺序完成构建、发布与探活，再处理注册中心上下线。任何一步失败，都能按版本回滚。

  • 多服务流水线、金丝雀灰度、定时计划与发布窗口
  • 多运行时发布：容器 / 静态站点 / Java jar / Go 与 Rust 单二进制 / Node 与 Python 进程，共用同一条发布与回滚链
  • 部署快照与版本对比，知道上一次到底改了什么
  • 服务依赖拓扑，发布前看清上下游影响

04 / AGENT

先出计划，
人工点头，再动生产。

在对话里描述目标，Agent 会结合服务状态、发布窗口与依赖生成计划；审批通过才创建任务。模型不可用时，规则引擎仍会给出归因与建议。

  1. 01
    计划读取项目、环境、服务与当前状态，生成可审阅的步骤与风险说明。
  2. 02
    审批操作员或管理员在 Web 审批单中确认；对话中的决策同样落入审计。
  3. 03
    执行复用平台原有的发布任务通道，不绕过发布窗口与回滚策略。
  4. 04
    留痕计划、审批人、任务结果与建议状态全部可追溯，案例可沉淀复用。
49 个运维工具 Web / CLI / MCP 六渠道巡检日报

模型是可选项。支持任意 OpenAI 兼容网关；不配置也不影响发布、监控和告警。

05 / LOCAL FIRST

它住在你的机器里。

Flask + SQLite 单机运行，SSH 直连目标服务器。项目配置、环境凭据和日志只保存在本机 data/platform.db，不经过第三方 SaaS。

单文件数据库备份、迁移、导入导出都在本机完成，数据库不需要额外的服务进程。
凭据不出内网平台不做云托管；SSH 由 paramiko 直连目标服务器，通知走你配置的渠道。
Windows 解压即用便携包内置 Python 3.12 运行时，不需要 pip、虚拟环境或开发工具链。

07 / FAQ

下载之前，
先确认几件事。

它面向的是一台到几十台服务器的自建环境，不是替代云厂商的整套 PaaS。

界面截图全部来自合成演示数据。展示页本身不收集任何运行数据。

和直接用 Jenkins 或发布脚本有什么区别？
平台不是替代 CI。构建可以继续交给 Jenkins；它补上的是发布前后的整条操作链：配置、任务、日志、回滚、监控、告警与审批在同一个项目模型里。适合没有专职平台团队、但需要可追溯发布的小团队。
一定要装 Docker 吗？
平台自身不需要 Docker。容器发布需要构建机或目标机具备 Docker；也支持静态站点包发布，以及 jar / Go / Rust 单二进制与 Node / Python 进程交给 systemd 托管（平台不代装运行时；Node 产物自带 node_modules，Python 依赖经 wheelhouse 离线装进 app_home/venv）。SSH 连接使用纯 Python 的 paramiko，不需要本机安装 ssh 客户端。
进程方式发布，服务会中断吗？
会。单实例的 jar / Go / Rust / Node / Python 发布在「停止 → 切换版本链接 → 启动」期间不可用；Python 依赖变化时还要在窗口内离线重装 venv，耗时可在任务日志查看。就绪验证失败会自动切回旧版本，但平台不承诺零停机。需要连续可用请改用容器多实例滚动发布。
能部署到 Linux 服务器吗？
平台本体是 Python 3.9+ / Flask 应用，可以运行在 Linux。当前提供的便携包是 Windows x64 版本；被发布的目标服务器通常是 Linux，通过 SSH 连接。
服务器密码和数据会离开本机吗？
平台不会主动上传配置。项目、环境、连接信息与日志存放在本机 data/platform.db。除非你主动配置外部 LLM 网关，否则运行链路不依赖第三方 SaaS。请像保护普通生产凭据一样保护这个数据库文件。
AI 助手必须配置模型吗？
不必。未配置 LLM 网关时会自动降级为规则引擎，发布、监控、告警与审批流程都不受影响。配置任意 OpenAI 兼容网关后，才会启用对话式编排和模型润色。
开源协议是什么？可以二次修改吗？
Apache-2.0。可以自部署、修改和分发，保留许可与版权声明即可。
